# NeuroGramLM Training Steps

This document outlines the workflow and mechanics of the main training loop for the NeuroGramLM architecture, specifically running via `scripts/train.py`.

## 1. Data Ingestion & Input Flow
- **Tokens in Data**: The model receives its training inputs exclusively from the tokenized JSON files generated by the `Neuro_Tokenization` module.
- **Dataloader**: The `Neuro_Dataloader` dynamically parses these tokens, chunks them to a maximum sequence length (preventing OOM errors), and converts them into batched PyTorch dictionaries (`inputs` and `targets`).
- **Autoregressive Shifting**: For teacher-forcing, the targets are shifted sequences of the input tokens. The dataloader handles this automatically.

## 2. Multi-Tower Forward Pass
During the training loop, the data is pushed through the multi-tower architecture of `NeuroGramLM`:
1. **Geometric Tower**: Processes the geometric tokens (tortuosity, curvature, inertia).
2. **Topological Tower**: Processes the topological tokens (Strahler order, Weisfeiler-Lehman hash).
3. **Bio Tower**: **The Bio tower receives no data during training.** The biological intensity mapping is bypassed (or passed empty/zeroed tensors) during this phase, as the model primarily focuses on learning the structural language of the neurons first. Biological embeddings are generally reserved for zero-shot or conditioned inference downstream.

## 3. Loss & Optimization
- **Mixed Precision**: The forward pass is wrapped in PyTorch Automatic Mixed Precision (`torch.amp.autocast`) to massively accelerate training on GPU Tensor Cores and halve the memory footprint.
- **Gradient Scaling**: The resulting composite loss (geometric + topological + structural fusion) is scaled via `GradScaler` to prevent 16-bit underflow.
- **Backpropagation**: Gradients are clipped to a norm of `1.0`, and the optimizer (`AdamW`) applies the updates. Memory is optimized heavily via `optimizer.zero_grad(set_to_none=True)`.

## 4. Cross-Validation & Checkpointing
- **Training/Validation Split**: The token data is split 80/20 at initialization.
- **Validation Pass**: Every **10 epochs**, the model runs a `torch.no_grad()` evaluation pass on the held-out validation set to compute the generalization loss.
- **Checkpoints**: The model state dictionary is saved incrementally and at periodic intervals to the designated `checkpoints/` directory.

To kick off training, ensure your GPU is cleared and run:
```bash
venv/bin/python scripts/train.py
```
